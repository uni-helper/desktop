## Findings considered and rejected

- **Multi-window support**: no README promise, example or TODO signals demand;
  the runtime's single-window assumption is deliberate. Revisit on a real use case.
- **Deep links / second-instance argv forwarding**: the single-instance lock
  (`runtime/index.ts:303-315`) is adjacent, but nothing in the repo hints at the
  need yet.
- **Windows/Linux dev-shell rebranding (mac-only today)**: README honestly
  documents the gap; no cheap fix exists on those platforms — fails the
  "disproportionately cheap" test.
- **uni.createPushMessage / notifications, getSystemInfo desktop-field patches**:
  H5 already implements them; patching would violate the repo's own
  "only uni-h5-unimplemented APIs" shim rule.
- **TECH-03 (`shared/assets.ts` importing the `ResolvedConfig` type upward)**:
  the existing `Pick<ResolvedConfig, ...>` parameter is arguably the simplest
  honest contract; a local structural type saves nothing.
- **CORR-06 (`pack.output` absolute path: `join` vs `resolve`, `pack.ts:61`)**:
  low likelihood a user sets an absolute output; fold a `resolve()` swap into
  the next pack.ts-touching plan instead of a dedicated one.
- **DX-03 (missing `.editorconfig`)**: ESLint covers ts/js; the residual yaml/md
  gap is trivial. Add antfu's standard file whenever convenient.
- **Coverage tooling / coverage CI job**: a percentage adds noise for a
  pre-release lib; the real gap (runtime execution tests) is plan 002.
- **`pnpm test` building before vitest**: intentional — the tsnapi
  snapshot guard refuses a stale `dist`; not a friction point.
- **esbuild / unconfig / @clack/prompts as dependencies**: each verified
  justified (watch-mode bundling, TS config loading, interactive prompts).
- **`@uni-helper/jsonu` 0.0.3 (early same-org dep)**: range is effectively
  exact-pinned and the manifest round-trip is locked by tests; acceptable risk,
  re-pin before any range loosening.
